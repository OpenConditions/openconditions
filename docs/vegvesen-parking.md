# Norway parking inventory qualification

`no-vegvesen-parking` reads static structured inventory from Statens vegvesen's [Parkeringsregisteret](https://dataut.vegvesen.no/dataset/parkeringsregisteret). Its scope is registered conditional parking. It does not establish comprehensive coverage of all parking or universal public access. The [registration guide](https://www.vegvesen.no/fag/trafikk/parkering/for-parkeringstilbydere/utfylling-av-felter) explains area splitting and future activation. The [dedicated read API](https://parkreg-open.atlas.vegvesen.no/ws/docs/openapi) documents `alle`, `kart` and optional organization filtering, with no pagination contract. This feed uses two national collection requests, with no per-ID fan-out, contacts join or OSM enrichment.

The feed remains disabled and `parkreg.qualified` remains false. On 2026-11-07, a single bounded national `alle` GET exceeded 96 MiB after 23.179 seconds and was stopped. It received HTTP 200, which does not establish completeness. The national `kart` request returned 22,951 unique IDs in 7,967,655 bytes and 7.086 seconds. No complete national full export or geometry comparison was established. No organization sample is represented as nationwide evidence.

Before activation, an operator must qualify a complete national `alle` response within an explicitly reviewed finite byte/deadline budget, compare all IDs with a contemporary `kart` response, inspect geometry sanity and active-version accounting, and record bytes, elapsed time and memory/load evidence. Do not repeatedly retry the oversized request at ordinary check cadence. Adjust the endpoint budget only with measured evidence, then set `parkreg.qualified` and remove `disabled` together. The parser independently rejects an unqualified feed, including when invoked through a worker or a live checker. Ordinary acquisition enforces the endpoint byte and full-body deadline limits in the shared acquisition framework; operator egress limits can tighten them further. Rights review is accepted; this remaining gate concerns load and completeness.

An eligible poll requires exactly one full collection and one map inventory with identical unique numeric IDs. An ID mismatch, duplicate ID, malformed collection, invalid active row, network error, truncation or budget failure rejects the replacement and preserves the last publication. A matched subset is authorized only when both configured national endpoints successfully return that set; changing endpoints to organization queries requires a separate source definition and qualification. A qualified empty answer or an answer containing only inactive/future/ended records explicitly permits an empty feature snapshot. A poll with an acquisition warning cannot authorize replacement, including when a scheduler has a held response available. Existing shrink guards still apply. This includes legitimate active-to-deactivated withdrawals. No-payload and unqualified empty responses have no such authority.

Only records with explicit null `deaktivert`, a current valid version and an active date interval publish a feature. Historical versions never create additional sites. Identity is the numeric area ID across revisions. Paid plus fee-free spaces form total capacity; disabled and charging counts are overlapping subsets and are never added to that total. Invalid counts reject the snapshot. Unknown or unspecified area types also reject it because the model requires a concrete site type; unknown park-and-ride tokens leave that usage unspecified. Garages are off-street without an inferred underground or multistorey layout. Coordinates are publisher geographic-degree points; the API does not formally identify a datum. No boundary is inferred.

Source version and modification time describe inventory revision. Retrieval is separately recorded as `fetchedAt`; no occupancy observation freshness is invented. The source emits no occupancy observations, prices, offers, opening hours, charger connectors or access guarantees. `rawRetention: none` prevents archiving full responses or holding role payloads between polls, including their assessment prose and media references; normalized output retains only the structured fields the parser selects. No PDF or image is fetched. The conservative daily cadence and two-day source freshness window are implementation choices, not publisher service guarantees.

The [product metadata](https://dataut.vegvesen.no/api/3/action/package_show?id=parkeringsregisteret) assigns NLOD, and the [national catalogue](https://data.norge.no/en/datasets/af5a2e69-7be0-30bd-99b1-734697cf72e5/parkeringsregisteret) identifies [NLOD 2.0](https://data.norge.no/nlod/no/2.0). Source credit, versioned licence link and the OpenConditions modification notice remain in catalogue attribution and public output. Upstream public-egress rights remain default-deny; this addition grants no rights to overlapping OSM records.
