# GeoNet earthquake acquisition

`nz-geonet-quakes` represents Earth Sciences New Zealand / GeoNet earthquake parameters under [CC BY 3.0 New Zealand](https://creativecommons.org/licenses/by/3.0/nz/). The [dataset metadata](https://data.gns.cri.nz/metadata/srv/api/records/5105fdeb-f314-4d6e-8e09-bf5308278e03/formatters/xml) supplies DOI [10.21420/0S8P-TZ38](https://doi.org/10.21420/0S8P-TZ38) and the historical citation: GNS Science. (1970). New Zealand Earthquake Catalogue [Data set]. GNS Science, GeoNet. The catalogue carries the current programme credit, modification notice, licence and [disclaimer](https://www.geonet.org.nz/disclaimer). This scope excludes external basemaps, images, felt reports and other GeoNet products.

The feed remains disabled. `runSource` also refuses ordinary scheduling even if an operator removes the catalogue flag. Its `geonetQualification: "contract-test"` dependency admits deterministic qualification runs; there is no environment override. Independent review and live reconciliation qualification must precede a separate activation change. Public requests need no credentials or publisher contact.

The worker discovers recent events with `/quake?MMI=-1` and the exact v2 Accept header. The recent list has a 100-event cap and a maximum one-year lookback. It is never treated as a complete snapshot. Every poll also scans overlapping, unthresholded FDSN origin windows over the last 72 hours, including other event types before classification. A supplementary `updatedafter` query overlaps the last committed coverage cursor by one minute. Exact-ID detail, history and QuakeML requests reconcile discovered events and all retained unexpired IDs, including those whose origin moved between windows. Preferred QuakeML origin and magnitude references supply precise typed values. Missing XML magnitude types remain absent. API depth is kilometres; XML depth is metres. Locality MMI is an allow-listed extra and never the model's maximum intensity. `-1` is omitted.

The 72-hour interval is an OpenConditions coverage policy. It does not describe the duration of an earthquake or establish a provider guarantee. Event validity is the origin instant, already ended. `freshness.expiresAt` ends coverage 72 hours after the preferred origin. An expired record is excluded from public reads and receives an `expired` tombstone; an explicit deleted or reclassified event receives `withdrawn`. Neither absence from the recent list nor FDSN 204 implies cancellation. Missing events retain their prior record and original expiry. All required requests must succeed before publication. Malformed records, missing partitions, HTTP errors and exhausted resource limits fail the entire attempt.

Publication uses partial writes and explicit dispositions under the source lock. Canonical validation failure rolls back the transaction. The coverage cursor commits with the records and source status. A concurrent poll that advanced coverage invalidates an older acquisition. Restart recovery reads retained IDs from PostGIS and rescans the bounded interval, without relying on a process-local cursor, ETag or payload cache. The normal expiry sweep also handles an outage that outlasts coverage. Consumers must not interpret an empty bounded coverage window as an all-clear notice.

The acquisition limits are local safeguards: 512 event IDs, 64 FDSN partition requests including 413 splits, a one-minute minimum split interval, 1,800 total HTTP attempts, 8 MB per decompressed response, 32 MB per poll and a two-minute deadline. Requests run sequentially. Transient 429/5xx responses receive at most two retries with cancellable exponential backoff. These values are not documented GeoNet quotas or service promises. A busy interval that exceeds a bound fails closed and requires qualification of revised bounds before activation.

The committed exact-event captures establish their recorded responses only. Their receipt contains retrieval completion times and SHA-256 hashes. Tests construct synthetic revisions and transport failures explicitly. Deterministic PostGIS tests do not establish sustained live load, catalogue completeness beyond the declared bounded interval or production acceptance.
