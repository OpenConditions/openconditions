# GeoNet earthquake acquisition

`nz-geonet-quakes` represents Earth Sciences New Zealand / GeoNet earthquake parameters under [CC BY 3.0 New Zealand](https://creativecommons.org/licenses/by/3.0/nz/). The [dataset metadata](https://data.gns.cri.nz/metadata/srv/api/records/5105fdeb-f314-4d6e-8e09-bf5308278e03/formatters/xml) supplies DOI [10.21420/0S8P-TZ38](https://doi.org/10.21420/0S8P-TZ38) and the historical citation: GNS Science. (1970). New Zealand Earthquake Catalogue [Data set]. GNS Science, GeoNet. The catalogue carries the current programme credit, modification notice, licence and [disclaimer](https://www.geonet.org.nz/disclaimer). This scope excludes external basemaps, images, felt reports and other GeoNet products.

The feed is enabled for bounded earthquake reconciliation without a manual attestation. The API/QuakeML disagreement for `2026p842957` is resolved by the selected-component policy below: API history `2026-11-08T21:30:01.678Z` matches preferred magnitude modification `2026-11-08T21:30:01.678579Z`, after event modification `2026-11-08T21:29:52.729711Z`. The committed exact captures retain all clocks and preferred references. Public requests need no credentials or publisher contact.

The worker discovers recent events with `/quake?MMI=-1` and the exact v2 Accept header. The recent list has a 100-event cap and a maximum one-year lookback. It is never treated as a complete snapshot. Every poll also scans overlapping, unthresholded FDSN origin windows over the last 72 hours, including other event types before classification. A supplementary `updatedafter` query overlaps the last committed coverage cursor by one minute. Exact-ID detail, history and QuakeML requests reconcile discovered events and all retained unexpired IDs, including those whose origin moved between windows. Preferred QuakeML origin and magnitude references supply precise typed values. Missing XML magnitude types remain absent. API depth is kilometres; XML depth is metres. Locality MMI is an allow-listed extra and never the model's maximum intensity. `-1` is omitted.

The 72-hour interval is an OpenConditions coverage policy. It does not describe the duration of an earthquake or establish a provider guarantee. Event validity is the origin instant, already ended. `freshness.expiresAt` ends coverage 72 hours after the preferred origin. An expired record is excluded from public reads and receives an `expired` tombstone; an explicit deleted or reclassified event receives `withdrawn`. Neither absence from the recent list nor FDSN 204 implies cancellation. Missing events retain their prior record and original expiry. All required requests must succeed before publication. Malformed records, missing partitions, HTTP errors and exhausted resource limits fail the entire attempt.

Publication uses partial writes and explicit dispositions under the source lock. Canonical validation failure rolls back the transaction. The coverage cursor commits with the records and source status. A concurrent poll that advanced coverage invalidates an older acquisition. API features and complete preferred-XML solution metadata commit as durable revision state with coverage. Subsequent generations compare incoming revisions against that state, rejecting older deletion and equal-clock conflicts. Named-field XML comparisons tolerate PostgreSQL JSON key reordering without erasing clocks or preferred references. The raw archive retains original response bodies and URL/digest/fetch identities under the existing rights policy. Restart recovery reads retained IDs from PostGIS and rescans the bounded interval, without relying on a process-local cursor, ETag or payload cache. The normal expiry sweep also handles an outage that outlasts coverage. Consumers must not interpret an empty bounded coverage window as an all-clear notice.

The acquisition limits are local safeguards: 512 event IDs, 64 FDSN partition requests including 413 splits, a one-minute minimum split interval, 1,800 wrapped fetch calls (including retries; redirects are separately bounded and validated by guardedFetch), 8 MB per decompressed response, 32 MB per poll and a five-minute deadline. Requests run sequentially. Transient 429/5xx responses receive at most two retries with cancellable exponential backoff. The original two-minute deadline expired after 306 responses for a 205-ID window, before the expected 619 requests could finish. Five minutes accommodates the observed serial rate within the ten-minute cadence; mixed-time captured-source qualification completed for all 205 IDs; sustained production load remains separate. These values are not documented GeoNet quotas or service promises. A busy interval that exceeds a bound fails closed and requires qualification of revised bounds before activation.

The committed exact-event captures establish their recorded responses only. Their receipt contains retrieval completion times and SHA-256 hashes. Tests construct synthetic revisions and transport failures explicitly. Deterministic PostGIS tests do not establish sustained live load, catalogue completeness beyond the declared bounded interval or production acceptance.

Revision reconciliation is conservative. An undated current API detail must match the newest dated history solution on geometry, origin, measurements, locality and quality before that history clock can be used. Conflicting ties, undated conflicting history and future clocks fail the entire poll. With no history, current detail retains its absent update clock. No retrieval time is substituted for a source revision time.

QuakeML retains event, preferred-origin and preferred-magnitude creation/modification clocks and both preferred references. Every duplicate pair is checked, including older ties. Different solutions use a componentwise partial order with at least one strictly newer clock and no regressing component. Classification or preferred-reference changes require a strictly newer event clock. Changed origin or magnitude data/references additionally require a strictly newer corresponding component clock. Equivalent UTC fractional spellings compare as nanosecond instants; distinct submillisecond revisions remain distinct. Exact-event responses have no special precedence over window results. Missing or conflicting ordering evidence fails reconciliation and preserves the last accepted rows and coverage cursor.

API and XML values are joined only when their available clocks and shared measurements agree. The [API](https://api.geonet.org.nz/) defines history modificationTime as the modification time of the returned information. QuakeML creation metadata belongs to individual objects, and GeoNet preserves SeisComP modificationTime on each object. The captured API information clock can follow a preferred-magnitude update after the event object's last update. Compatibility therefore uses the latest clock among the event and its resolved preferred origin and magnitude, never unselected magnitudes. This is a local join policy supported by the captured values, not a claim that the event clock globally orders all objects. A missing event clock still fails a dated API join. Shared origin, geometry and measurements must also agree.

The API capture truncates XML microseconds to milliseconds. A three-digit API fraction can match the corresponding XML millisecond bucket; finer supplied precision requires exact nanosecond equality. Whole-second clocks are not widened into a tolerance window. Origin time follows the same rule. Coordinate tolerance is 0.00000001 degrees, depth tolerance 0.001 metre and magnitude tolerance 0.000001, based on captured serialization precision rather than provider accuracy guarantees. SourceUpdatedAt retains the selected API history clock exactly; raw XML and durable preferred metadata retain the full component clocks. Fetch time never becomes source update time.

Missing optional API measurements remain absent; they do not supply zero or a magnitude scale. Supplied invalid values, dangling preferred references, unknown classification/evaluation tokens, ambiguous structures and incorrect XML namespaces fail before deletion/reclassification can publish. Supported BED elements use the QuakeML 1.2 namespaces; the captured SeisComP modificationTime and passedQC extensions are recognized explicitly.

Large acquired generations use the normal parse child with original XML response buffers and selected API/durable metadata. Acquisition validates revision authority before the child, and its resulting drafts must agree exactly with the child's output before publication. The checker uses the same bounded acquisition rather than treating capped discovery as complete. The qualification replay used 613 recorded responses at the original coverage anchor, including an 84-response later suffix; it establishes mixed-time capture compatibility and local publication, not a fresh ordinary HTTP run, sustained load, production-container acceptance or production readiness.
