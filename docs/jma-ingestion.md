# JMA ingestion checkpoint

The `jma-xml` worker uses durable acquisition and native report reconciliation. It does not parse JMAXML as CAP. Both catalogue feeds remain disabled. The earthquake worker has a PostGIS/API regression; the warning worker refuses activation because an authoritative bootstrap has not been qualified. Rolling recent and long indexes provide incomplete coverage, including after recovery. A successful poll records `partial`, never a complete active-warning census.

Every process sharing a provider-visible egress IP must use the same database and the same explicit `OPENCONDITIONS_JMA_EGRESS_ID`. Both JMA feeds share this key. Separate databases or inconsistent keys do not enforce a shared quota. The daily allowance is 8,000,000,000 bytes per UTC day, below JMA's 10 GB threshold. Each request reserves its maximum body allowance before transport. A completed read settles to observed body bytes. Transport or guard failures can conceal bytes already consumed, so their reservations remain charged for that day, including across restarts. Uncertainty can exhaust the day's allowance; it is never blindly refunded. Eight days of counters are retained. One transient transport/5xx retry uses another reservation and a short abortable delay within the poll deadline.

Payload URLs are restricted to the official HTTPS data path with redirects refused. Recent indexes have a one-minute cadence and long indexes an hourly cadence. Polls are serial, bounded to 1,000 selected messages, 8 MB per response and a two-minute deadline. Families are filtered before payload acquisition. Immutable bodies persist across restarts. Files outside a 45-day download horizon are refused; bodies older than 45 days are removed during reservation. The cache refuses new entries at 25,000 rows. These ceilings fail the poll and preserve the last publication; they do not assert complete recovery.

Earthquake publication retains thirty days by the source Control revision clock. Older earthquake units and tombstones are removed together, and incoming reports behind the same advancing floor are ignored. The long index cannot resurrect a removed unit behind that floor. An event folds the newest uncancelled family into one situation; cancelling a family leaves other families intact. Warning state retains omitted areas and explicit release tombstones; only a supplied source `ValidDateTime` can expire a warning. Storage shares each native report across area references, with a maximum 20,000 areas, 4,096 product units and 32 MB serialized lifecycle state. Exceeding these limits rolls back publication and cursor updates.

The office filter currently accepts only 気象庁, 気象庁本庁, 札幌管区気象台 and 横浜地方気象台, as represented in the pinned official fixtures. Unknown publishing or editorial offices fail the entire poll. This is a conservative implementation subset, not a complete review of co-publishers or upstream material. Public API, archive and federation withholding for every upstream rights case remains an acceptance requirement. No GIS geometry, logos or independent forecasts are included. JMA's native XML and wording remain available alongside the normalization credit and CC BY 4.0 alternative notice.

Remaining acceptance includes warning bootstrap and worker publication, all warning-family API lifecycle regressions, explicit upstream rights clearance and public-projection withholding, the full operational header/code/XSD and qualitative-value matrix, and bounded live qualification. Local fixture and PostGIS tests do not establish these claims. Python, independent interop, production audits and OCI qualification are separate checks.
