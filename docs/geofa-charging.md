# Denmark GeoFA charging inventory

`dk-geofa-charging` reads the current GeoFA Ladefacilitet layer. It includes public records (`off_kode=1`), administratively current (`statuskode=3`) car facilities (`ladefacilitet_type_kode=1`) with public charging access (`tilgaengelighed_type_kode=1`). Physical plan status 1 is operational, 2 planned, and other values unknown. Administrative state and system-version times do not report live operation. No availability measurements, linked tariffs, media, contacts or case information are published. Coverage can omit nonmunicipal land and update schedules vary.

The parser accepts one point in a MultiPoint, in CRS84/WGS84 or checked EPSG:25832, and refuses other geometry. Administrative dates use Copenhagen midnight through the midnight after the end date, including daylight saving changes. Facility identity uses `objekt_id`; `versions_id` is provenance. All six international ID columns remain as nonfederated evidence. Only distinct named IDs agreeing with the stated point count become EVSEs. A facility plug label is assigned only when there is one EVSE and the spelling explicitly identifies Type 2. CCS alone is ambiguous. Energy use in kWh and power class never become numerical charging ratings.

The [GeoDanmark terms](https://www.geodanmark.dk/home/vejledninger/vilkaar-for-data-anvendelse/) cover GeoFA under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Records carry linked @geodanmark credit, the licence and an OpenConditions normalization notice. The linked privacy policy concerns the website and secretariat; it is not a charger-data privacy guarantee. Upstream content remains subject to ordinary default-deny rights checks.

## Acquisition and withdrawal authority

The catalogue enables the non-withdrawing scope qualified by replaying the lawful current-day capture through the actual enabled checker, parse child, registry, disposable PostGIS and public API. This is captured-poll qualification; a fresh ordinary HTTP poll and production operation remain unproven. All 34,652 supported facilities and 32,758 components were checked through database storage and all 70 API pages, including exact expiry.

The bounded 2026-11-09 current-layer traversal returned 35,830 rows and 35,825 unique facility IDs. Each of five repeated IDs occurs twice inside one page, with different version IDs but identical other projected fields and geometry. Non-withdrawing parsing preserves the agreeing facility assertion and all version IDs in `geofaVersions`, without selecting a singular authoritative revision. Any other projected difference rejects the whole poll. These repeated source versions are not offset-boundary duplicates.

EVSE claims are assessed across all eligible, currently valid facilities, including rows with unresolved counts. A shared normalized EVSE identity leaves every claiming facility unresolved: its raw IDs and count remain evidence, with no components. Distinct source facilities may describe the same physical installation; their preservation does not establish a count of physical chargers. Component-key collisions still reject the poll. No row order, coordinates or version timestamp chooses an EVSE owner.

The configured `main.geofa.nonWithdrawing` mode checks hits before and after a sorted offset traversal using the observed Danish collation. It requires nondecreasing IDs, reconciled row counts, CRS and page, byte and time bounds. Equal IDs pass to parser integrity reconciliation; decreasing IDs, failed pages, capped responses, count drift and empty results publish nothing. WFS advertises `PagingIsTransactionSafe=FALSE`: even equal hits and reconciled rows cannot prove all concurrent edits were captured. This is an observed partial inventory with no absence-based withdrawal authority. A successful poll updates observed facilities; absent facilities retain last-good until expiry. Each facility expires after two days or earlier at its administrative validity end. This expiry does not report charger closure or live status.

An optional independently qualified publication `count` and canonical `sha256` remain supported for complete-snapshot operation when non-withdrawing mode is absent. A matching digest proves identity with that qualified set; it cannot itself establish national completeness or transaction safety. The ordinary shrink guard still applies to complete snapshots. Normal non-withdrawing refreshes do not need per-generation digest attestation.

Acquisition uses offsets of 2,000 (the policy also supports 500), at most 100 pages, 32 MiB and 900 seconds total. These are local bounds, not publisher quotas. Failed attempts receive a process-local daily cooldown, cleared on restart. Source rights and static scope filters apply in both modes. Combined schema/shared-contract integration and production qualification remain separate controller tasks.
