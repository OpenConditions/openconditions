# Product 0.8.1

This release resets the database migration history to one generated baseline and reworks the `conditions` schema before OpenMapX's first production install. It needs a fresh database and new operator steps.

## Action

- **Start from a fresh database.** A database created by an earlier build is not upgraded. Drop the `conditions` schema, or the whole database, and the old `drizzle.__drizzle_migrations_oc` table before starting the ingest service.
- **Set the new required secret `OPENCONDITIONS_SECRETS_KEY`** (64 hex characters, `openssl rand -hex 32`) on the ingest service, the heavy-feeds process, the contributions API and, when enabled, federation.
  - Generate it once for the ingest service and copy the same value to the others. Under OpenMapX, enter it on each service's Credentials page.
  - The first ingest process to start seals it, and a service with a different key refuses to start.
  - Keep it in your recovery set. Under OpenMapX, also keep OpenMapX's own secrets key, which encrypts it in the vault.
- **Create the roles before the ingest service first starts.**
  - `openconditions_ingest` owns `conditions` and keeps `CREATE` on the database at every start. The heavy-feeds process and federation connect as this role.
  - `openconditions_contributions` is the contributions API's role.
  - Give both `search_path = conditions, extensions`.
  - At every start the ingest service grants this role, and OpenMapX's `openmapx_tiles_owner`, exactly what they use. A role created later gets its grants at the next ingest start.
- **Rebuild the OpenLR resolver graph.** It now lives in its own schema `openlr`.

## Changes

- **Migrations:** only the ingest processes migrate, and the history lives in `conditions.__drizzle_migrations`. The contributions API and federation wait for the schema version, for up to five minutes by default.
- **Encryption:** OAuth tokens and the issuer and federation private keys are stored encrypted with AES-256-GCM.
- **Crowd reporters:**
  - They are deleted 12 months after their last activity, with their votes, refusals and quotas.
  - Deleting a reporter removes its key from what it reported.
  - Several unneeded reporter columns are gone.
- **Schema conventions:**
  - Every constraint and index follows one naming convention.
  - Identity ids replace `bigserial`.
  - Closed value sets are checked.
  - The observation tables store fixed-width columns first.
- **Retention:** a series' history is read and purged within its current retention, across retention classes.
- **Ordering:** SMN messages come back in a deterministic order.
- **API:** `/feeds/status` no longer reports `unknownStatus`.

Compatibility details, every schema difference and the deferred items are in `docs/release-notes/database-baseline.md` and pull request #455.

Deploy together with OpenMapX releases that contain OpenMapX/openmapx#1079.
