# Product 0.8.2

This release settles the database, configuration and crowd protocol before OpenMapX's first production install. It replaces 0.8.1, which was prepared but never published, and includes everything 0.8.1 contained. It needs a fresh database and new operator steps.

## Action

- **Start from a fresh database.** A database created by an earlier build is not upgraded. Drop the `conditions` schema (under OpenMapX only that schema) and the old `drizzle.__drizzle_migrations_oc` table before starting the ingest service.
- **Set `OPENCONDITIONS_INSTANCE_ID` on every service before the first start**: ingest, the heavy-feeds process, the contributions API and, when enabled, federation, all to the same lower-case DNS name, usually the instance's public host name. It has no default any more. The first ingest process seals it in the database, every service then refuses another id, and it cannot change later.
- **Set the required secret `OPENCONDITIONS_SECRETS_KEY`** (64 hex characters, `openssl rand -hex 32`) once for ingest and copy the same value to the heavy-feeds process, the contributions API and federation. The first ingest process seals it. Keep it in your recovery set.
- **Under OpenMapX, set `OPENCONDITIONS_RELAY_TOKEN`** (at least 32 characters) on the contributions API to the same value as OpenMapX's own. Relayed enrollments then share one relay limit (`OPENCONDITIONS_RELAY_ENROLL_LIMIT_PER_MINUTE`, default 600) instead of the 10 a minute one address gets.
- **Create the roles before the ingest service first starts**: `openconditions_ingest` (owns `conditions`, keeps `CREATE` on the database; heavy feeds and federation connect as it) and `openconditions_contributions`, both with `search_path = conditions, extensions`. Ingest grants them, and OpenMapX's `openmapx_tiles_owner`, what they use at every start.
- **Rebuild the OpenLR resolver graph.** It lives in its own schema `openlr`.

## Changes

- **Migrations:** one generated baseline; only the ingest processes migrate, with the history in `conditions.__drizzle_migrations`. The contributions API and federation wait for the schema version.
- **Instance identity:** a required, sealed instance id (`conditions.instance_identity`), checked as a DNS name in configuration, peer and actor configs.
- **Encryption:** OAuth tokens and the issuer and federation private keys are stored encrypted with AES-256-GCM.
- **Crowd protocol:** every signed report and vote body carries `"v": 1`; others are refused with `400` and `CLAIM_VERSION_UNSUPPORTED`. Clients must sign the new member.
- **Crowd reporters:** deleted 12 months after their last activity, with their votes, refusals and quotas; deleting a reporter removes its key from what it reported.
- **Relay trust:** the contributions API trusts an authenticated relay for its enrollment limit; a wrong bearer is logged without the token or address.
- **Manifests:** every service manifest declares `platform: "1.0"`, `quality: "community"` and `configSchema.required` for what it cannot start without; the extension declares `AGPL-3.0-or-later`.
- **Schema conventions:** one naming convention for constraints and indexes, identity ids, checked value sets, fixed-width columns first.
- **Retention and ordering:** series history is read and purged within its current retention; SMN messages come back in a deterministic order.
- **API:** the ingest OpenAPI document describes the routing, speed and status routes OpenMapX reads, and paths never break. `/feeds/status` no longer reports `unknownStatus`.
- **Federation guide:** the compose example uses OpenMapX's real network and volume names and pins the image to the release tag.

Details are in `docs/release-notes/database-baseline.md`, `docs/release-notes/pre-launch-contracts.md` and pull requests #455 and #460.

Deploy together with OpenMapX releases that contain OpenMapX/openmapx#1083.
