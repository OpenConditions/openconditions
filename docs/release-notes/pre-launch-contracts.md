# Instance id, relay trust, claim version and manifest rules

Affected versions: The first product release containing this change and every later one. No product version is assigned by this change.

Action: Set `OPENCONDITIONS_INSTANCE_ID` before the first start, on every OpenConditions service of the instance: the ingest service, the heavy-feeds ingest process, the contributions API and the federation service, all to the same value. It has no default any more (it was `local`). Use a lower-case DNS name, usually the instance's public host name, for example `maps.example.org`. A service without it, or with a value that is not a DNS name, stops at start. The first ingest process to start seals the id in the new table `conditions.instance_identity`, and every service then refuses to start with another id. The id cannot change later. To use another one, stop the OpenConditions services and drop the `conditions` schema (under OpenMapX only that schema, never the shared database), then start again with the new id. See [the instance id](../../README.md#the-instance-id).

Under OpenMapX, set `OPENCONDITIONS_RELAY_TOKEN` on `openconditions-contributions-api` (a vault secret, at least 32 characters, `openssl rand -hex 32`) to the same value as OpenMapX's own `OPENCONDITIONS_RELAY_TOKEN`. OpenMapX relays every user's crowd requests from its own address; with the token, those requests share one relay enrollment limit, `OPENCONDITIONS_RELAY_ENROLL_LIMIT_PER_MINUTE` (default 600), instead of the 10 enrollments a minute one address gets. A set token shorter than 32 characters stops the service at start. See [behind a relay](../../services/contributions-api/README.md#behind-a-relay).

Compatibility:

- Crowd protocol: every signed report claim and sub-claim body carries the top-level member `"v": 1` inside its signed bytes. The contributions API refuses a report or vote without it, or with another version, with `400` and `code: "CLAIM_VERSION_UNSUPPORTED"`. Clients must sign the new member; signatures made without it no longer verify. Claims name no target instance, deliberately; see [the wire contract](../../packages/contrib-core/README.md#claim-version).
- Instance ids: a configured instance id must be a DNS name (labels of letters, digits and inner dashes joined by single dots, at most 253 characters). Ids such as `a..b` or `a-.b`, which the earlier check let through, are refused.
- Database: the baseline is regenerated with the table `conditions.instance_identity` (one row, `instance_id` checked as a DNS name). The contributions role may read it. A database created by an earlier build is not upgraded, as for the earlier baseline.
- Manifests: every service manifest declares `"platform": "1.0"` and `"quality": "community"` (`community-verified` is gone). The extension declares `AGPL-3.0-or-later`, the licence of the services it installs; it declared `Apache-2.0`. Each service manifest lists what the service cannot start without in `configSchema.required`: the database URL, the secrets key and the instance id on the ingest services (and the feeds it polls on the heavy-feeds process), the grant secret and reviewer token too on the contributions API, and the database URL and instance id on the federation service. OpenMapX applies a configuration only once every enabled service has a value or a stored secret for each, and names the missing ones.
- Federation guide: the compose example names OpenMapX's network `openmapx_openmapx` and the ingest volume `openmapx_openmapx-openconditions-ingest-data`, and pins the image to the release tag.
- API: the ingest OpenAPI document describes the routing, speed and status routes (`/feeds/status`, `/valhalla/exclusions.json`, `/segments.geojson`, `/segments/speed.csv`, `/segments/profiles.json`, `/segments/conditions.json`). Paths never break; a breaking change gets a new path.
