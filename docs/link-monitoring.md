# Link monitoring

The Monday and manual `Link check` workflow checks Markdown with lychee 0.24.2 through the existing pinned action. It retains the Markdown glob, Git-ignore behavior, `.lycheeignore` exclusions, one-day cache, three direct npm metadata endpoints, curl retry/connect/request limits and 360-minute runner bound. It runs only on the owning repository's main branch, checks out the workflow SHA without persisted credentials and supplies a token only to the github-script reporting step. Curl children also strip both reporting-token variables. No Git subprocess or custom API client is needed.

The validator requires successful checkout, setup, checker, version and registry steps. It accepts lychee exit 0 for complete healthy output and exit 2 for complete broken-link output; missing exits, tool/configuration exits 1/3/127, missing/malformed output, empty or inconsistent coverage and incomplete registry checks fail visibly. HTTP and recognized transport failures remain endpoint diagnostics. Complete unhealthy checks remain nonfatal after successful reporting, preserving the existing monitoring policy. Summary, report generation and API failures fail the job.

The human-readable summary records source SHA, run/attempt, time, response counts, exclusions, unsupported responses and cache hits. Cached responses are not necessarily fresh network checks; counts do not prove every possible repository link was requested. Concise input/URL/error diagnostics go into the report; raw JSON and registry results remain ordinary three-day workflow artifacts. These are monitoring diagnostics, without release or signed provenance authority.

The reporter uses github-script's supplied GitHub client and pagination with retries disabled. It finds one open, fixed-title issue owned by the GitHub Actions bot, preserves legacy diagnostic bytes and human text outside a managed section, refuses edited or ambiguous managed diagnostics, rereads before writing and verifies the response and readback. An uncertain write stops without retry or rollback. The managed checksum detects edits; it is unsigned. The last read and write are not atomic, so a human edit in that gap remains possible. Workflow concurrency serializes only this producer's runs.

New reports use the existing `documentation` label. Healthy checks recommend manual resolution review and make no issue request. The workflow never automatically closes or reopens issues, adds comments or activates lifecycle policy. Main integration includes PR259's label-reference change; no taxonomy activation is implied. Local tests and PR CI do not establish scheduled/manual execution, real provider acceptance, live API behavior or notification delivery.
