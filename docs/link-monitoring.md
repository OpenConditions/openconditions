# Link monitoring

The existing Monday and manual `Link check` workflow checks Markdown with the pinned lychee action and checks three npm registry metadata endpoints directly. Its Markdown glob, Git ignore behavior, `.lycheeignore` URL exclusions, one-day cache setting and curl retry/connect/request limits are preserved. No short job timeout was inferred from unrelated measurements; the runner's existing 360-minute bound remains.

A fresh execution directory records the owning repository, immutable source SHA, workflow run and attempt, start/completion times, tool identity, exclusions and coverage. The finalizer requires successful checkout, Node setup, preparation, lychee and registry steps. It validates lychee's JSON counters and diagnostics against its exit code and requires all three direct endpoint results. Missing, empty, malformed, contradictory or unknown evidence fails visibly. Lychee exit 2 means completed broken-link checks; exits 1/3 indicate execution/configuration failure. A partial or missing result cannot become zero failures.

`checksComplete` records checker completion independently from overall `complete`. Complete healthy checks retain evidence and recommend manual resolution review without changing an issue. Complete unhealthy checks retain the diagnostics and refresh the fixed bot-owned broken-links report; successful reporting preserves the existing nonfatal broken-link policy. Infrastructure, evidence, report generation, API/readback and summary failures fail the workflow. Curl's recognized HTTP/transport failures remain reported endpoint failures; startup, configuration, local IO and unrecognized exit failures are infrastructure failures.

Coverage counts include total/unique responses, successes, errors, timeouts, exclusions, unsupported links, cache hits and three registry endpoints. Cached responses are not necessarily fresh network observations. Excluded and unsupported links are limitations, not successful provider checks. Input coverage follows lychee's existing extraction and ignore semantics; counters are not proof that every possible link in the repository was requested. Raw lychee JSON, registry diagnostics, the rendered report and execution receipt are retained as ordinary workflow artifacts for three days. Checksums detect byte changes and are not signed provenance or release authority.

Only trusted owning-repository main schedule/manual execution can report. Checkout uses the exact workflow SHA without persisted credentials. The action receives an explicit empty token; the reporting token is supplied only to the finalizer, and all its Git/curl subprocess environments strip both reporting-token variables. The helper accepts no freeform repository, API URL, endpoint, ref or issue selector. Local tests use owned HTTP servers and temporary Git repositories; they perform no live provider or issue mutation.

The report requires the existing `documentation` label. It identifies an open issue using the fixed title and GitHub Actions bot identity, rereads it before updating and verifies the write response and fresh readback. Earlier diagnostic bytes and human text outside the managed section are preserved. Edited or ambiguous managed diagnostics, competing updates and uncertain writes stop without retry or rollback. The checksum is unsigned and API reads plus writes are not atomic; a remaining human edit in the final read/write gap cannot be ruled out. Workflow concurrency serializes this producer's own runs, not human edits. No issue is automatically closed, reopened, commented on, relabeled or assigned a type.

Source/process tests and ordinary PR CI do not qualify native scheduled/manual execution, real providers, notification delivery, protected-main operation or live taxonomy activation. Those gates require merged sources and legitimate operational evidence; no test workflow dispatch or issue submission is needed for this source PR.
